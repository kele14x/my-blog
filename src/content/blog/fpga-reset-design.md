FPGA 或 ASIC 设计应该使用同步复位还是异步复位？对于 FPGA，我们很容易用厂商的名字来回答：Xilinx 推荐同步复位，Altera 推荐异步复位。而谈到 ASIC，一种常见说法是：异步复位寄存器比同步复位的实现方式需要更少的晶体管。

这些说法可能符合某些具体实现，但都不是普遍成立的规则。FPGA 把逻辑映射到既定的硬件结构上，标准单元 ASIC 则把逻辑映射到所选的单元库中。真正重要的问题是：**有哪些可用的硬件资源或单元，完整实现的代价是什么，以及讨论的是复位路径中的哪一部分？**

在选择复位策略之前，先把三个问题分开：

1. 目标寄存器使用的是同步复位输入，还是异步复位输入？
2. 相对于这个寄存器的时钟，复位信号是同步到达的，还是异步到达的？
3. 整个设计应该如何进入复位状态，又如何恢复正常运行？

这几个问题彼此相关，但不能混为一谈。

本文中的“置位”指复位信号进入有效电平，“释放”指回到无效电平。因此，置位不一定是拉高：高电平有效的复位信号置位时是拉高，低电平有效时则是拉低。图中的 `PRE` 引脚仍称为“预置”输入，表示将寄存器输出置为 `1`。

## 同步复位寄存器和异步复位寄存器

我们从第一个问题开始看：“目标寄存器使用的是同步复位输入，还是异步复位输入？”先看一个高电平有效的异步复位寄存器：

```verilog
always @(posedge clk or posedge arst) begin
    if (arst) begin
        data <= 1'b0;
    end else if (cen) begin
        data <= din;
    end
end
```

`arst` 置位时，不需要等待时钟边沿就会清零 `data`。这段代码通常会映射为带有异步清零输入的寄存器，具体还取决于 FPGA 提供的原语或 ASIC 使用的标准单元库。释放 `arst` 本身不会把 `din` 装入寄存器；正常的数据采样要等到后续时钟边沿才会恢复。

同步复位的写法略有不同：

```verilog
always @(posedge clk) begin
    if (rst) begin
        data <= 1'b0;
    end else if (cen) begin
        data <= din;
    end
end
```

这里的 `rst` 只在 `clk` 上升沿被采样。它的优先级高于时钟使能，但**时钟停止时，它无法让寄存器复位**。它还必须满足接收寄存器的建立时间和保持时间要求。根据目标架构和单元库，综合工具可能使用专用的同步控制输入，也可能在数据路径上加入逻辑来实现复位。这里我们就看到了同步复位的第一个好处：由于复位是同步的，综合工具有可能通过数据路径来“模拟”复位，从而实现某些优化目标。

注意，并不是说你把第一种写法改成第二种写法，复位信号就自动被同步了。如果把未经同步处理的外部复位直接接入第二个例子，那么实际上你是在同步电路中引入了一个异步输入。

## 异步复位也有时序要求

“异步复位不需要考虑时序”是一种常见的错误认识。对于寄存器本身，异步复位信号置位时，不需要等待时钟边沿，只要满足最小脉宽等复位要求，寄存器就会进入复位状态。但是在释放复位时，如果过于接近时钟有效边沿，就可能违反恢复时间或移除时间要求。寄存器可能进入亚稳态，不同寄存器也可能在不同的周期退出复位状态。

<img src="/images/fpga-reset-design/fpga-async-timing.drawio.png" alt="带异步清零输入的寄存器及其时序图，标出了一个时钟上升沿之后的移除时间，以及下一个上升沿之前的恢复时间。" width="643" height="193" loading="lazy" decoding="async" style="background-color: white;" />

*恢复时间与移除时间检查约束的是异步复位的释放。*

- **恢复时间（recovery）**：从复位释放到下一个时钟有效边沿之间所需的最小时间间隔，可以类比建立时间。
- **移除时间（removal）**：时钟有效边沿之后，复位必须继续保持有效、不能立即释放的最小时间间隔，可以类比保持时间。

复位信号的脉冲宽度也需要满足寄存器的最小脉宽要求。读到这里，你可能有点疑惑：异步复位不是不需要时钟吗，为什么还要考虑时序？不需要时钟的是复位信号置位后的生效过程，释放仍有时序要求。因此，同步复位和异步复位都需要时序分析，只是检查的类型不同，不能认为采用异步复位就能省去时序收敛的工作。

如果系统允许，可以先无毛刺地停止时钟，再完成复位的置位和释放。复位信号仍需满足最小脉宽要求，释放时也仍需满足 recovery/removal 要求。不过，我们可以通过控制流程，让复位释放远离停钟前的最后一个有效边沿，并在复位释放到达所有目标寄存器、留足恢复时间后，再重新启动时钟。这样就能获得更充足的时序余量，使复位时序更容易满足。需要验证的是各寄存器引脚处的实际时序，而不只是控制器发出信号的先后顺序。

## 当复位源是异步信号时

然后我们再来看第二个问题：“相对于这个寄存器的时钟，复位信号是同步到达的，还是异步到达的？”

如果复位信号相对于目标时钟已经同步，而且到达目标寄存器时满足相应的时序要求，一般就不需要再加同步器。不过，把信号接到复位引脚，并不会自动产生正确的时序约束；仍需正确约束时钟和相关路径，并确认工具执行了应有的检查：同步复位端的置位和释放要满足建立时间（setup）和保持时间（hold）；异步复位端的释放要满足恢复时间（recovery）和移除时间（removal）。

如果复位信号来自外部复位引脚、另一个时钟域，或者由 PLL 的锁定指示信号产生，就不能直接假定它与目标时钟同步，通常需要采用下面的同步方式。对于同步复位端，要处理置位和释放两个过程；对于异步复位端，可以保留异步置位，但必须保证释放安全，也可以采用前述受控停钟流程。**关键是满足目标端的时序要求，而不是不分来源和使用方式，给所有复位信号再加一个同步器。**

这里有两种常见的同步方式。

### 异步置位，同步释放

<img src="/images/fpga-reset-design/fpga-async-rst-async.drawio.png" alt="由多个寄存器组成的寄存器链，ARST_IN 连接到每一级的异步预置输入，第一级数据输入接零，最后一级输出 ARST_OUT。" width="781" height="281" loading="lazy" decoding="async" style="background-color: white;" />

*复位通过预置引脚异步生效，再通过时钟驱动的寄存器链同步释放。*

在这个高电平有效的电路中，`ARST_IN` 驱动同步器每一级的异步预置输入。复位信号置位时，各级寄存器和 `ARST_OUT` 都会变为 `1`，不需要等待 `CLK`。输入释放后，零会随着后续时钟边沿逐级传递，直到 `ARST_OUT` 变为 `0`。

额外的级数为亚稳态消退提供了时间，降低复位释放传播到其他逻辑时仍受亚稳态影响的概率。通常要求至少 2 级，但并不保证在所有场景下都满足可靠性要求。增加级数通常可以**提高平均故障间隔时间（MTBF）**，代价是增加释放延迟。它降低的是故障概率，而不是从根本上消除亚稳态。只不过，当故障概率足够低、满足设计的可靠性要求时，我们就可以在工程上将其忽略不计。

应使用目标工具能够识别的同步器实现方式、属性和时序约束方法。例如，AMD 的 [XPM_CDC_ASYNC_RST](https://docs.amd.com/r/en-US/ug974-vivado-ultrascale-libraries/XPM_CDC_ASYNC_RST) 提供异步置位、同步释放功能。即使它能够展宽输出脉冲，异步输入仍然必须满足最小脉宽要求。

当复位必须在时钟启动前或时钟停止期间生效时，这种方式很有用。释放则需要等待时钟运行。因为**只有释放过程被同步了，置位过程仍然是异步的**，所以我们将这种同步方式称为“异步置位，同步释放”。一般来说，异步复位寄存器会采用这种方式来同步复位信号。

### 置位和释放都同步

<img src="/images/fpga-reset-design/fpga-async-rst-sync.drawio.png" alt="由时钟驱动的寄存器链，ARST_IN 仅连接到第一级的数据输入，各级复位引脚固定为无效电平，最后一级输出 RST_OUT。" width="781" height="281" loading="lazy" decoding="async" style="background-color: white;" />

*这就是一个普通的单比特同步器。*

这里，`ARST_IN` 进入第一级的数据输入，而不是各级的异步控制引脚。置位和释放这两种跳变都在 `CLK` 的驱动下逐级传递，因此经过同步延迟后，`RST_OUT` 的置位和释放都由时钟边沿触发。

这样可以避免寄存器链输出端的异步置位，但也带来了不同的要求：

- 目标时钟必须运行，置位或释放才能向后传递。
- 输入必须保持有效足够长的时间，才能被可靠采样。短脉冲可能被漏掉。
- 启动时，必须确保已知的复位状态在正常运行使能之前到达目标逻辑；未初始化的寄存器链并不能保证上电复位。

同步后的输出既可以驱动同步复位寄存器，也可以驱动异步复位寄存器，但必须分别满足目标端的时序要求：同步复位端检查建立时间和保持时间，异步复位端在释放时检查恢复时间和移除时间，同时还要满足最小脉宽要求。检查时，需要计入源寄存器的时钟到输出延迟，以及复位树和时钟树的延迟与偏斜。**输出经过同步，并不意味着所有目标端的时序就自动满足了。**

需要注意：**加入复位同步电路，并不会把寄存器的异步复位引脚变成同步复位引脚，反过来也一样。**

## 系统的复位设计

接下来我们考虑第三个问题：“整个设计应该如何进入复位状态，又如何恢复正常运行？”我们先来看看同步器没有解决什么问题：

考虑一个采用异步置位、同步释放电路的异步复位寄存器，它的输出连接到没有被复位的逻辑：

<img src="/images/fpga-reset-design/fpga-async-issue.drawio.png" alt="复位释放同步器驱动寄存器 A 的异步预置输入；A 的输出连接到寄存器 B，B 的预置输入固定为无效电平。所有寄存器共用 CLK。" width="732" height="381" loading="lazy" decoding="async" style="background-color: white;" />

*即使 A、B 使用同一个时钟，复位的置位仍然可能让寄存器 A 的输出在两个时钟边沿之间发生变化。*

复位的置位可以沿着下面的路径传播：

`ARST` → 同步器的预置输入 → 同步器输出 → 寄存器 A 的预置输入 → 寄存器 A 的输出 → 寄存器 B 的数据输入。

这个例子中，寄存器 B 的预置输入固定为无效电平。因此，它可能在时钟边沿附近采样到由复位引起的数据输入跳变。仅靠释放同步器，并不能保护这条路径。

这并不是说所有采用异步复位的流水线都有问题。实际的功能风险取决于哪些接收逻辑仍在运行、复位的分发方式和偏斜，以及复位期间的数据是否会影响控制状态或存储器写入。应根据设计需要，对受影响的接收逻辑进行复位、暂停其活动，或采用其他隔离措施。

## FPGA：Xilinx/AMD 与 Altera 的建议

不同厂商对于如何设计复位有不同的建议，但这些建议并不是无条件适用的规则。

**Xilinx/AMD 通常建议：在需要复位时，优先使用同步复位。** [UltraFast 设计方法学指南 UG949](https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Synchronous-Reset-vs.-Asynchronous-Reset) 解释了原因：同步复位能提供更灵活的资源映射。例如，DSP48 和块 RAM 内部的寄存器支持同步复位，而不支持异步复位。如果相关流水线寄存器使用异步复位，综合工具就可能无法把它吸收到这些硬核资源中。

**Altera 的通用设计建议在讨论全局复位时，更倾向于采用同步释放的异步复位。** [Quartus Prime Pro Edition User Guide: Design Recommendations](https://docs.altera.com/r/docs/683082/current) 的 3.3.1.3 节介绍了异步置位、同步释放的方式：既利用异步复位资源，又控制释放时序。这并不是建议把一个释放时刻不受控制的外部复位直接分发到整个设计。

**Altera 针对 Hyperflex 架构的建议是一个重要例外。** [AN 917: Reset Design Techniques for Hyperflex Architecture FPGAs](https://docs.altera.com/r/docs/683539/current) 的 1.1.2 节说明，Hyper-Register 没有异步复位功能。使用同步复位，才能在寄存器重定时（retiming）过程中利用这些资源，因此带异步复位的寄存器可能成为这类优化的障碍。

另外，还要区分「复位某个硬件块的输出寄存器」与「清空它的存储内容」。如果对 RTL 中 RAM 数组的每个元素都执行复位，可能导致综合工具无法推断出块 RAM；仅仅把整个数组的异步复位改成同步复位，并不能解决这个问题。

因此，真正有用的原则是：**遵循目标器件系列、原语和 IP 的要求，而不是只看厂商名字。**

## ASIC：标准单元、面积与复位架构

对于标准单元 ASIC，不需要适配 FPGA 中既定的硬件结构。复位方式会影响综合工具选择哪些库单元，以及需要在周围加入什么逻辑。前面讨论的时序和同步原则仍然适用，但面积和系统层面的取舍需要重新评估。

### 异步复位需要更少的晶体管吗？

**在某个具体单元库中，它可能更经济，但不能笼统地认为「异步复位一定使用更少的 MOS 晶体管」。** 应该比较完整的实现，而不只是两种复位方式的名称：

- **异步复位**：使用内部集成了异步复位电路的寄存器。
- **同步复位**：使用普通寄存器加数据输入端的复位逻辑；如果库中提供专用的同步复位寄存器，也可以直接使用。

对于不带时钟使能、复位值为零的单比特寄存器，同步复位的数据输入函数可以写成 `D_eff = D & ~rst`。它并不天然需要一个完整的多路选择器，综合工具也可能把复位功能合并到已有的数据输入逻辑中。反过来，在普通寄存器中加入异步复位，同样需要额外的内部电路；复位引脚并不是没有代价的。

集成的异步复位单元面积可能小于「普通寄存器加独立复位逻辑」，但结果取决于实际的单元和映射方式。晶体管数量也不等于单元面积：晶体管尺寸、驱动能力、版图、复位极性，以及可用的扫描单元类型都会影响结果。应比较映射后的面积、功耗和时序，并计入复位缓冲与布线的代价，而不是预设能节省固定数量的晶体管。

Cummings、Mills 和 Golson 在 [*Asynchronous & Synchronous Reset Design Techniques—Part Deux*](https://trilobyte.com/pdf/CummingsSNUG2003Boston_Resets_rev1_2.pdf#1#5#1) 的 4.2–4.3 节讨论了这种区别：同步复位逻辑可以使用更小的寄存器，但新增的组合逻辑可能抵消这部分节省；并非每个 ASIC 库都提供专用同步复位单元。因此，结论取决于单元库，不能说哪一种复位在面积上总是占优。

### 为什么在 ASIC 中选择异步复位？

有两个实际理由，与晶体管数量无关：

- **不依赖运行中的时钟**。在已经供电且满足正常电气工作条件的域中，异步复位可以在时钟启动前或被门控关闭时建立确定状态。同步复位则需要启动流程在复位有效期间提供时钟边沿。
- **避免在 D 路径上加入额外的复位选择逻辑**。合适的异步复位单元可以让这部分功能不占用寄存器外部的数据输入路径。这可能有利于时序关键路径，但仍需比较单元自身的建立时间和时钟到输出延迟；异步复位并不自动意味着更快。

同一篇论文的 4.3 和 5.3 节介绍了这些取舍。它们使异步置位、同步释放成为一种实用的 ASIC 复位策略，但并不要求所有寄存器都采用这种方式。在时钟可用性、单元映射和系统复位行为允许的地方，同步复位同样适用。

## 如何选择复位策略

与其把各种组合简单标为「可以」或「不可能」，不如从实际需求出发：

- **复位必须在没有时钟时生效**：目标寄存器需要支持异步复位，同时要有合适的置位路径。释放时应满足各目标端的恢复时间和移除时间要求，通常分别同步到各个目标时钟，也可以采用前述受控停钟流程。
- **复位可以等待时钟运行**：在满足资源和 IP 要求的前提下，置位与释放都经过同步的复位信号，配合同步复位寄存器，通常是合适的选择。
- **时钟被门控或暂时停止**：同步复位在这段时间内无法生效。但如果启动控制器能先启用时钟，再让复位跨越足够多的有效边沿保持有效，最后才允许逻辑开始工作，仍然可以采用同步复位。
- **设计包含多个时钟域**：对需要同步处理的目标时钟域，分别使用复位同步器。已经同步到时钟 A 的复位，对于与 A 无关的时钟 B 并不会自动变得安全。如果不同模块之间存在依赖，应安排释放顺序，或通过握手确认彼此已就绪，而不是假设它们会同时启动。
- **关心资源推断、单元面积或寄存器重定时**：检查映射后的实现，而不是假设某一种复位方式代价更低。对于 ASIC，要把所选单元库和扫描单元纳入比较；对于 FPGA，要检查硬核资源推断和重定时限制。只复位真正需要复位的状态；有时只复位控制状态和数据有效标志，就足以避免使用数据通路中尚未初始化的值。

最后，还要验证最小脉宽、时钟是否可用、释放顺序，以及实现后的复位分发情况。保留异步复位目标端的恢复时间/移除时间检查，以及同步复位目标端的建立时间/保持时间检查。即使对进入已识别同步器的原始异步源设置时序例外，也不应因此盲目关闭其下游复位路径的检查。

在同一个 FPGA 或 ASIC 中同时使用两种复位方式并不矛盾。目标不是让所有寄存器都遵循同一句口号，而是让实际硬件进入和退出复位的行为可预测。
